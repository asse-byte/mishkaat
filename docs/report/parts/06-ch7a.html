Chapter 7Database Design and Data Dictionary

7.1 Choice of a document store

The persistence layer is MongoDB 7. The choice is defensible on three grounds specific to this domain, and it carries one cost that the design pays explicitly.

  • The academic record is naturally document-shaped and evolving. A recitation acquired an optional page count and a map of error tags after the system was in use; a competition contestant carries an array of per-judge marks whose length varies with the size of the panel; a message carries an array of attachment descriptors and an array of replies. In a relational schema each of these is a join table and a migration.
  • Read patterns are aggregate and scope-filtered. Almost every screen asks for “all rows for this set of students” — a single $in query on an indexed field. The system deliberately avoids per-row queries (§5.8), and a document store serves this shape well.
  • Operational simplicity. One database process, one backup artefact — and, because uploaded files live in GridFS inside the same database, one restore brings back logos and attachments with the records that reference them.
The cost, and how it is paid A document store enforces no referential integrity and no uniqueness unless asked. The design therefore treats unique and partial indexes as business rules, not as performance hints: attendance uniqueness per student per day, certificate uniqueness per student per milestone, XP uniqueness per (student, reason, source) and badge uniqueness per (student, badge) are all database constraints. An application-level check followed by a write is not atomic — two simultaneous clicks each find nothing and each insert — which is precisely the duplication the check was written to prevent.

7.4.1 The access path expressed as relationships

The authorisation chain of §3.2 is a traversal of four of these relationships in reverse: users._id → teachers.user_id → halaqat.teacher_id → students.halaqah_id. Because each link is a plain indexed field rather than a materialised permission table, changing a circle's teacher changes that teacher's visibility on the next request, with nothing to synchronise and no stale grant to revoke.
