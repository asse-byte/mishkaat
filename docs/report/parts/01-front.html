Front MatterAbstract

Mishkaat (المشكاة, “the niche that holds the lamp”) is a production-oriented, multi-tenant web platform for the administration and academic supervision of Qur'an memorisation centres (دور تحفيظ القرآن). It replaces the paper registers, isolated spreadsheets and oral reporting on which such centres traditionally depend, with a single auditable system covering six user roles, eleven functional domains and a full analytical layer.

The system is built as a three-tier application: a React 19 / TypeScript single-page front end (installable as a Progressive Web App), a FastAPI / Python asynchronous REST back end exposing 136 endpoints across 22 routers, and a MongoDB document store of 28 application collections plus a GridFS binary store, governed by 71 index definitions created at application start-up.

Beyond conventional record keeping, Mishkaat contributes an analytical engine that converts raw recitation and attendance records into interpretable academic signals: a four-class weighted error taxonomy, five per-student performance metrics computed at read time (mastery, momentum, precision, consistency and review depth), a multi-feature ordinary-least-squares model that forecasts Juz' and full-Qur'an completion dates from memorisation quality as well as quantity, and a multi-criteria motivation layer of four independent leaderboards, ten achievement badges, four periodic challenges and an append-only experience-point ledger.

Security is treated as a first-class functional requirement rather than a deployment concern, because the platform stores identifying data about children. The report documents a layered control set: short-lived access tokens with refresh-token rotation in an httpOnly cookie, a token revocation list with user_version invalidation, dual-key (per-IP and per-account) rate limiting, Fernet field-level encryption of personally identifying student attributes at rest, a SHA-256 hash-chained audit log with atomic sequencing, content-sniffing file-upload validation, and a single-gate authorisation model whose scope boundaries — system, centre, حلقة (study circle) and self — are defined in one module and asserted by 314 isolation assertions across seven test suites.

This document specifies the problem domain, the delimited scope, the stakeholder model, the functional and non-functional requirements, the architecture, the complete data dictionary and relationship model, the API surface, the mathematics of the analytical engine, the security architecture, the business workflows, the user interface, the verification strategy, the operational topology, and the system's measured limitations and forward work.
